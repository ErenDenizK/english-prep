# v0.71 — Visible, responsive scenes and a living atmosphere

Research: 4 October 2026. The requested reference is Duolingo's expressive
animation language. English Prep remains an academic article-and-test app;
teaching content, completion rules and question outcomes are unchanged.

## Source evidence and its limits

The following official sources were retrieved over verified HTTPS and read:

1. [Rive's official case-study index](https://github.com/rive-app/awesome-rive#case-studies)
   contains a **Duolingo** section, linking the official Duolingo article
   [Art meets technology: the next step in bringing our characters to life](https://blog.duolingo.com/world-character-visemes/)
   and the presentation
   [How we Animate the Duolingo World](https://www.youtube.com/watch?v=fgOqvyPif3g).
   This is verified evidence of the case-study relationship, **not** a transcript
   or observation of the current Duolingo app. The linked blog and video, the
   Duolingo design site and Rive customer pages returned proxy **403** here.
   No Duolingo timing, retention uplift or frame-rate measurement is invented.
2. [Rive State Machine Overview](https://github.com/rive-app/rive-docs/blob/main/editor/state-machine/state-machine.mdx)
   defines animations as connected states, with explicit transitions. Its own
   button example uses Idle, Hovered and Clicked. That is useful for responsive
   artwork: a drawing responds to an event rather than merely looping behind a
   control.
3. [Rive Transitions](https://github.com/rive-app/rive-docs/blob/main/editor/state-machine/transitions.mdx)
   separates direction, conditions, properties and actions. It warns that states
   without conditions can immediately skip forward. Its Exit Time option can
   deliberately hold a transition until an animation has played. English Prep
   explicitly avoids that hold for navigation, answers and focus: user input
   changes the actual state immediately and interrupts decorative presentation.
4. [Rive Interpolation](https://github.com/rive-app/rive-docs/blob/main/editor/animate-mode/interpolation-easing.mdx)
   distinguishes constant-speed, cubic and elastic behavior. Cubic curves permit
   gradual starts and finishes; elastic motion overshoots and settles, with
   amplitude and period controlling the effect. Its graph-editor discussion
   explains anticipation and follow-through even when final positions match.
   Those are techniques, not reasons to bounce every paragraph or UI control.
5. [Rive Web's official runtime](https://github.com/rive-app/rive-wasm)
   provides JavaScript/WASM, artboards and state machines with canvas rendering.
   It is a valid production option for complex authored characters. This app's
   small SVG illustrations can express the chosen states with native CSS and
   the existing cancellable Web Animations API. A new asset/runtime stack would
   add loading work without a needed character rig, so this iteration retains
   the dependency-free static application.

The earlier [official motion-system source comparison](2026-10-motion-v070.md)
still informs the distinction between immediate control feedback and longer
expressive artwork. The requested “Duolingo spice” is interpreted as purposeful
personality and responsive parts, not a claim to reproduce Duolingo's internals.

## Diagnosis and choices

The baseline atmosphere moved only 20–28 CSS pixels per leg over 28/34/42
seconds. Much of each gradient lived in a corner. Increasing opacity would make
the page brighter without solving the missing movement. Baseline artwork also
started when constructed, even if its route, font or screenshot had not yet
become visible. A longer animation alone would still play at the wrong moment.

| Concern | Decision | Reason |
| --- | --- | --- |
| Art finishes before it can be seen | Start a finite scene after its target is visible and its relevant assets are ready; cancel obsolete work. | Presentation follows actual arrival rather than request start time. |
| Abrupt icon movement | Give illustrated parts a gentle anticipation, a readable action and a short settling phase. | Related parts communicate one cause-and-effect sequence. |
| Fragmented introduction | Treat illustration, selector and explanation as one shared region; selected state reshapes that region. | A common surface and persistent composition make its parts belong together. |
| Every click should respond | Update selection, focus and actual application state immediately; decorate the local result. | A longer illustration never becomes input latency. |
| Repeated clicks | Replace the previous presentation channel and settle obsolete targets. | No queued story continues after the learner has moved on. |
| Prose readability | Keep text opaque and stationary during artwork choreography. | Animation should reveal relationships, not turn reading into tracking motion. |
| Continuous atmosphere | Three fixed pigments travel and breathe on different cycles; their overlaps create local color changes. | Color can feel alive without an uncontrolled hue sweep or extra layers. |
| Pause choice | One preference in Settings, with OS reduced motion and hidden-page pause preserved. | Controls remain predictable and the interface avoids repeated toggle rows. |

The authored timing is an application design decision. The longer flow/trace
role is for decorative scenes; it does not delay completion, quiz scoring,
navigation or storage. It is not advertised as an empirical Duolingo duration.

## Aurora architecture and contrast envelope

The same three pigments remain `#c65b88`, `#785ca8` and `#c68571` at the existing
maximum per-field alpha **0.10 dark / 0.05 light**. Each occurs once. There is no
new blend mode, brightness filter, hue rotation or animated gradient stop.
Transform and element opacity are the only continuously animated properties.

Each lobe now ends at transparency **inside its own layer**, before that layer
moves. A first rendering pass caught a hard rectangular edge where a translated
corner gradient was still colored at its boundary; centered, fully contained
falloffs corrected it. The centers travel by 20–22 viewport-width percentage
points and 15–16 viewport-height points across several soft poses. Durations are
**16, 21 and 27 seconds per alternating leg**, with different starting phases.
Element opacity ranges from 0.45–1, never increasing the audited alpha cap.
The independent movement changes the mixture seen at any particular place.

This preserves the existing palette checker's assumptions: at most three
distinct pigments, ordinary source-over composition, fixed pigment endpoints
and maximum alpha bounds. Its 15 single/double/triple overlap orders remain
conservative. The initial verification passes **7,848** overall contrast pairs;
the limiting supporting-text ratio over the atmosphere remains **7.18:1 dark /
5.43:1 light**, and control boundaries remain at least **3.19:1 / 3.22:1**.

No requestAnimationFrame loop or pointer tracking is added to the background.
Off and hidden states pause it; OS reduction uses a composed static background;
forced-colors and print remove the decoration. This is not an energy or physical
phone frame-rate guarantee; browser compositing and pixel evidence is recorded
below after the final visual pass.

## Browser pixel comparison

The actual old and new stylesheet were rendered in local Chromium at 390×844
and 1440×1000, at device pixel ratio 1. An isolated diagnostic host loaded the
production CSS and motion module with no foreground content. Each CSS animation
was paused and set to the same deterministic timeline positions: 2, 4, 7 and 12
seconds after creation. The initial 2-second sample avoids startup paint effects.
The table compares **2 seconds with 7 seconds**. RGB difference is in 8-bit
channel units; this is an objective pixel change, not a perceptual quality score.

| Viewport | Before: mean absolute RGB change | After | Before: area changing ≥3 in any channel | After |
| --- | ---: | ---: | ---: | ---: |
| 390×844 | 0.305 | 1.965 | 0.1% | 40.2% |
| 1440×1000 | 0.276 | 1.936 | <0.1% | 39.7% |

Maximum local channel change over the same five-second span rises from 3 to 12.
The increased signal comes from movement and different pigment proportions,
not a higher alpha cap. The final 390px render was visually inspected for the
previous straight gradient edge; its falloff is continuous. These samples do
not claim equal noticeability on every display or while opaque cards cover the
background.

An isolated 1.2-second running interval reported **0 extra layouts, style
recalculations and script duration** through Chromium's Performance metrics.
Computed styles confirmed `filter: none` on all three fields. The attempted CDP
LayerTree inspection returned no layer events in this headless environment, so
GPU layer promotion and GPU cost are **not** claimed as measured. The properties
are compositor-eligible; that is a design choice rather than a hardware promise.

In a separate browser check, saved motion-off and synthetic hidden-page events
paused all three fields and their transforms/opacity remained unchanged after
250ms. Emulated OS reduced motion removed the animations and kept the explicit
static composition unchanged. The existing six motion preference/lifecycle unit
tests also pass. A synthetic visibility event does not replace background-tab
testing on a physical phone.
