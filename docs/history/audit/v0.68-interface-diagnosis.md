# v0.68 — Interface diagnosis and implementation boundaries

Date: 2026-10-04. Baseline: `c92be0c` (v0.67). This is an audit and recommendation, not a claim that the redesign is implemented or validated.

The owner's complaint is about visual hierarchy, atmosphere and product craft, not a request to change the article/test learning model. Keep the role-based reading typography established by ADR 006, English language attributes, source material, one reading lane, two content tabs and optional identity. Reconsider that ADR's palette, finite-only atmosphere and one-page introduction in response to this new feedback.

## Method and limits

Inspected `CLAUDE.md`, ADR 006 and the real renderer/CSS, then ran Chromium at 320×740, 390×844 and 1440×960 against the app on port 8010. Measurements wait for fonts and route animation settlement. Local evidence is in `/tmp/ep68-interface-audit/measurements.json` and corresponding screenshots. Random pretest questions vary per fresh context, so their measured heights are examples, not corpus maxima. No horizontal document overflow occurred in these sampled states. This does not prove all content or enlarged-text states are safe.

The browser probe briefly captured a profile route during its outgoing view transition; that image was discarded and the settled route measured again. Do not report an outgoing animation snapshot as a persistent rendering bug. Automated pointer scrolling also precedes clicks; option stability must be measured after `scrollIntoViewIfNeeded()` rather than mistaking the driver's scroll for answer reflow.

## Introduction: three deliberate pages, not a configuration wizard

Use a short optional tour with three pages, explicit `1 / 3` state, Back/Next and a visible `Atla` action throughout. Do not auto-advance. Existing return visitors and deep links must not be forced through it.

1. **Identity + Eğitim.** Wordmark, one sentence explaining the audience, then a compact illustrative flow: `Konuyu seç → Dersi oku → Örneklerle ayırt et`. Show a realistic miniature lesson outline or preview. Explain that the main teaching content is scrollable reading, not flashcards.
2. **Test + useful return.** Show `Soruyu çöz → Nedenini gör → İlgili derse dön`, with a restrained answer/feedback demonstration. Mention wrong-answer practice briefly. Do not invent content unlocks, lives, streaks, mastery or a new tab.
3. **Ready.** A concise privacy fact and optional name. The final action is `Derslere geç`; leaving the name blank works. A secondary route can lead directly to Test only if it does not complicate the simple final choice.

Each page has one heading and one visual illustration, not another nested panel grid. A 180–240ms opacity/short translation can link pages; buttons respond immediately. With reduced motion, replace content immediately. Keep visible step state and controls outside the transitioning panel. On step change, focus the new heading with `preventScroll`; first reset the shared scroll region to its intended position. Do not give hidden/outgoing content tabbable controls or duplicate heading IDs.

At 320×568 and 200% text, the panel must grow and scroll rather than clip to a fixed slideshow height. Place controls after the content or in an actual non-overlapping footer. When the name keyboard opens, the submit control remains reachable; Enter submits only the final name step. Preserve the typed name when going Back then Next. Fast double clicks must neither skip steps nor invoke completion twice. Closing or skipping must not write an empty name over an existing name. The final action must have a deterministic real route.

Recommended ownership: `js/onboarding.js` and dedicated onboarding CSS; root integrates brand/colors and route motion. Existing `home.js` optional hash flow can remain; any new first-visit entry must respect explicit lesson/test deep links.

## Pretest default-open: progress geometry must change with it

Current `readFraction()` uses `scrollTop / (scrollHeight - clientHeight)`. Despite its old comment, this is top-of-viewport scroll progress, not the bottom's absolute reading position. The pretest and its answer explanation therefore consume part of the lesson's progress. Opening/collapsing them changes the denominator; scrolling through a long preliminary answer can record a material percentage before any article content has been read. Its removal on a later opening changes what the saved fraction points to.

A coherent minimal fix uses a stable **instructional-content start** marker:

- In `renderLesson()`, identify the first real teaching block after the heading and pretest (including a grouped pitfall block). Add a class or data attribute to the existing node rather than a new wrapper that would change `.lesson` gap or direct-child styling.
- Add one `readerGeometry()` helper used by both `readFraction()` and `openLesson()` restoration. In scroll-content coordinates, `start = firstBlock.getBoundingClientRect().top - scrollRegion.getBoundingClientRect().top + scrollTop`; `end = scrollHeight - clientHeight`.
- For `end > start`, report `clamp((scrollTop - start) / (end - start), 0, 1)`. The heading and preliminary question contribute zero reading progress. Answering/expanding the pretest moves both the instructional start and the end together; content-relative progress is stable once within the article.
- Restore a positive stored fraction to `start + fraction * (end - start)`. Restore zero to the top so a first arrival sees its title/pretest. A completed reread still starts at top. Use the same helper, or the new display and old restore coordinate systems will disagree.
- When `end <= start`, do not return `1` merely because the instructional body is short: if a tall pretest is still above it, only mark completion after the end of the real content is reached/visible. For a whole short lesson that already fits the viewport, the existing completion semantics can remain. Clamp all denominators and ranges.
- A pretest `Derse geç` action should collapse the disclosure or scroll to the marker using the fixed-header offset, then focus a real heading as appropriate. It must not mark the lesson complete, answer the question or add a test attempt.
- Set `pretestOpen: Boolean(pretest)` only when constructing a fresh reader for an unread lesson. Re-rendering the check must retain `reader.pretestOpen`, `answers` and question selection; manual collapse must not be undone by a feedback render. The existing guard against a queued `toggle` event mutating a newer reader should stay.
- Keep the single shared question taker, which already prevents the pretest from repeating inside the article checks. Existing in-memory answers need not gain a new storage schema solely for this visual refinement.

Existing saved fractions were measured against the entire page. They can remain valid fractions, but a same-percent resume will move modestly after the reading-boundary correction, as it already can when content height changes. Document that limitation rather than pretending to preserve exact sentence anchors. A durable block/offset bookmark would be a separate migration, unnecessary here.

### Tests required for the default-open change

1. Fresh unread lesson: pretest open, options visible, bar and stored reading fraction zero even after scrolling within a long pretest or its full explanation; no test-history mutation.
2. Correct and wrong pretest answers: same option rectangles before/after after driver scrolling has settled; focus stays on selected option; disclosure remains open; article progress does not jump.
3. Collapse/reopen the pretest: explicit state persists, no forced expansion on answering; skip reaches the first real block with no content hidden beneath the fixed bar.
4. Scroll the instructional content to a known fraction, navigate away and resume: no pretest, restored normalized body position within rounding tolerance. Repeat after a viewport resize and with a short article.
5. Finish at the real bottom: completion recorded. Staying at the end of pretest alone never records completion. Revisiting a completed lesson starts at top without the pretest.
6. Rapid topic/lesson navigation: stale queued toggle/scroll callbacks do not mutate the new lesson. The existing navigationVersion and reader identity guards remain intact.
7. Keep the collision test for the pretest and inline question pools. Exercise long Closest Meaning and short grammar options at 320/390/1440.

Repository expectation to update: `tools/verify-ui.mjs` `runPretest()` currently explicitly asserts closed-by-default then clicks the summary. Its comment should reflect actual unread-vs-read behavior. Avoid silently deleting the old stability, collision and reread checks.

## Recommended implementation order and acceptance

First repair geometry/proximity (resume, topic hover, signal text, progress metrics, settings) and pretest state/progress. Apply the measured palette and semantic markers after those roles are explicit. Then implement the short introduction, motion system and all-screen ambient layer. Last, create About screenshots from the final real interface and build the expandable portfolio around actual features. This avoids producing attractive marketing media for obsolete screens.

Verify keyboard focus, screen-reader names and progress labels; 320px reflow; 200% text and WCAG text-spacing overrides; dark/light/system; correct/wrong/unanswered states; empty/part-filled/full progress; reduced motion and pause; and final real screenshots after fonts and transitions settle. Contrast checks substantiate visibility, not aesthetic quality. Visual review must still reject unnecessarily boxed, undifferentiated or distracting compositions.
