# v0.69 interaction and component review

Reviewed 4 October 2026 (Türkiye), baseline `9e68e84`. This audit concerns the
interface only: no article, question, explanation, option, category or stored
learning-history schema needs to change.

## Method and measurements

`home.js`, `quiz.js`, `shell.js`, and both CSS layers. Drove Chromium at 320×740,
390×844 and 1440×1000 through Test, the question-count menu, Profile reset dialog,
and the Present Perfect vs Past Simple article's open pretest. Normal motion
was enabled. The three widths had no horizontal document overflow.

these temporary review files are reproducible with the described routes and

## Prioritized fixes

### P1 — Native dialog padding currently dismisses it

A click 6px inside the dialog's top-left corner closed it at 390px. The handler
checks `event.target === dialog`, but native dialog padding also has the dialog
as its target. Compare client coordinates with the dialog's bounding rectangle:
only a point outside that rectangle is a backdrop click. Retain native focus
containment, Escape, cancel-first focus and platform focus restoration. Opening
may animate the surface/backdrop; cancellation and confirmation must commit
immediately. Never delay deletion, cancellation or focus behind animation.

### P1 — Answer state is not available when revisiting an option

After answering, the current buttons have `aria-disabled=true`, an aria-hidden
check/cross glyph, and color classes. Neither `aria-label` nor
`aria-describedby` communicates “correct answer” or “your incorrect answer”
when returning to an option. The shell's initial announcement is good, but does
not solve revisiting. Add a Turkish visually hidden state description and use
`aria-describedby`, retaining the English answer span and its language. Do not
change the visible source option or make a committed answer a radio button.

Keep the conventional check/cross geometry: these distinguish success/error
without hue. Color is an accent and should not make all four options look like
new cards after selection. Draw a short check/cross arrival at its already
reserved position. Avoid shaking the selected answer, changing row dimensions,
moving it, or dimming the other options below reading contrast.

### P2 — Menu state needs clearer shape and local motion

The menu has no arrival cue; the trigger's only transition is a 220ms transform.
A selected option is indicated by text color alone, while the keyboard-active
option has an inset focus outline. Add a fixed-width trailing check slot for the
committed value, separate from active keyboard position. Give the chevron its
own class and rotate it on `aria-expanded`; animate the popup once from its
anchor edge. Expose `data-side=top|bottom` after existing positioning. Keep all
keyboard contracts, viewport anchoring, fixed/popover positioning and immediate
selection. Closing remains immediate so no invisible menu intercepts a second
action; do not animate height or menu-item reordering.

### P2 — Quiz repeats its entire entry fade after an answer

`renderQuestion()` creates an `.animate-in` page every time, including an answer
commit and option reveal. This fades existing question/option text again. Use
route/question entry only when the question identity changes. Feedback itself
already inherits a 220ms `rise-in` from the historical CSS layer; replace that
with an explicit short, local cue in the current motion system, and keep prose
legible at once. Score, disabled state and next-action availability are instant.

The embedded lesson check already pins scroll position and restores the selected
button's focus. Preserve this, and never animate pretest/article height: doing
so changes the reading-progress geometry and shifts content beneath a thumb.

### P2 — Shared controls have inconsistent inherited motion

The switch thumb and tab indicator still inherit historical spring durations,
while current buttons use 100ms presses and 160ms paint changes. Listbox and
row transforms also have separate durations. Use shared press/state/navigation
tokens, with a single restrained easing family. Disabled/aria-disabled controls
must not compress on press. Focus rings appear immediately; changes of focus
must never be delayed or faded. Tab labels and icons should respond together,
while the selected marker can slide behind them. Menu and disclosure chevrons
carry state; decorative icons need not animate forever.

### P3 — Lines and boxes should express structure, not accumulate

The current answer cards preserve a neutral fill and reserve a glyph column;
this is a useful starting point. Keep one edge per actionable object, avoid
adding another bright outline to every answered card. The pretest already has
a parent surface, so its summary can use a custom rotating chevron rather than
adding extra separator decorations. Profile groups and topic rows should keep
consistent internal padding and use spacing for subsection separation. A
subtle hover/focus surface or directional icon cue is preferable to adding more
permanent borders. All reading text stays stationary under pointer motion.

## Interaction acceptance matrix

| State | Desired response | Must remain immediate/stable |
| --- | --- | --- |
| Hover on interactive row/button | Local surface + optional tiny arrow travel | Text layout, target size |
| Pointer press | Brief ≤1px compression/translation | Commit on native click |
| Keyboard focus | Visible high-contrast ring | Focus itself and reading order |
| Dropdown open | Short anchored arrival; chevron rotation | `aria-expanded`, focus and active option |
| Dropdown commit/close | Selected check updates; close immediately | Value, callback, focus restoration |
| Dialog open | Short surface/backdrop arrival | Inert background and cancel focus |
| Dialog confirm/cancel/Escape | Close immediately | Action/result and focus restoration |
| Answer | Check/cross cue and local feedback | Scoring, source text, answer row geometry |
| Next question | One brief question arrival | Counter and next question availability |
| Switch/tab | Shared short state movement | Setting / navigation commit |
| Reduced motion / user motion off | Static state changes | All functionality |

## References that govern this review

- [WAI-ARIA select-only combobox example](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/): retain active descendant, selected value and keyboard behavior.
- [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): native focus containment and restoration; least destructive action when appropriate.
- [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): correct/chosen state needs a non-color cue.
- [WCAG 2.3.3 Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): preference disables nonessential interaction movement.
- [MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog): use the platform's modal semantics, not a parallel hand-built focus trap.

These standards guide the recommendations; the timings above are application
choices coordinated with the v0.69 motion research, not timings mandated by
WCAG or claims of user testing.
